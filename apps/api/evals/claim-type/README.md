判定方式：与 `dataset.jsonl` 的 `expected` 逐条比；两层断言都在本地跑，**不进 CI / `check-dev.sh`**。

```bash
pnpm --filter @know-fit/api kb:eval:check   # 标注够不够（≥20）
pnpm --filter @know-fit/api kb:eval         # 跑评测
```

## 2026-10-23 首次实跑

## ⚠️ 这 40% 不是「判得准不准」

标注由助手生成，**未经作者逐条复核**（`metadata.label_status = pending_author_review`）。其中第 8–20 条按**视频是「背部跟练」**整段标成「演示」（`label_basis = video_metadata`），但按 `prompt.txt` 的定义，这些片里大量是动作要领口述（事实）和训练建议（观点），不是跟练口令。

所以这次实跑证明的是：

1. promptfoo → 百炼端点 → 提示词 → 解析这条链**通了**；
2. 标注规则在「片级」上还**没定义清楚** —— 300–600 字的片经常把观点、事实、演示混在一起，单标签本身是模糊的。

**在作者定下「片级主类怎么判」并复核标注之前，不要引用 40% 当准确率。**
